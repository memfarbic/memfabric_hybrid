# MemFabric Hybrid 项目总览

## 项目概述

MemFabric Hybrid 是一款开源内存池化软件，面向昇腾超节点和服务器等。其设计目的与核心思想是：

1. **异构设备的统一池化**: 将多节点的异构设备内存（DRAM|HBM等）池化，提供高性能的全局内存"直接访问"能力
2. **简单的北向接口**: 提供内存语义访问接口，即 xcopy with global virtual address，向传统的 memcpy 概念靠近，支持 D2RH\RH2D\RH2H\D2D 等
3. **南向高可扩展**: 通过插件的方式支持多种 DMA 引擎和 LD/ST 及多种网络/灵衢互联（Device UB、Device RoCE、Host UB、Host RoCE 等）

## 整体架构

MemFabric 主要分为四大模块：

```
┌─────────────────────────────────────────────────────────────┐
│                        API Layer                            │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐   │
│  │  BM API  │  │ SHM API  │  │Trans API │  │Python API│   │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘   │
├─────────────────────────────────────────────────────────────┤
│                    Global Memory Management                 │
│         (GVA 全局编排、页表映射策略、驱动注入)               │
├─────────────────────────────────────────────────────────────┤
│                      Data Operation                         │
│              (xcopy 实现，xDMA、LD/ST 驱动)                 │
├─────────────────────────────────────────────────────────────┤
│                   Transport Management                      │
│      (链接管理，QP/Jetty 链接建立，用于 RDMA/UDMA)          │
├─────────────────────────────────────────────────────────────┤
│                    acc_links (通信层)                       │
│              (基于 TCP 的进程间控制命令通信)                 │
└─────────────────────────────────────────────────────────────┘
```

### 四大核心模块

| 模块 | 行数 | 文件数 | 职责 |
|------|------|--------|------|
| `util/` | 2,707 | 17 | 公共工具函数（日志、锁、文件工具等） |
| `acc_links/` | 6,364 | 35 | 内部通信层（基于 TCP 的进程间控制命令通信） |
| `hybm/` | 27,970 | 137 | 内存管理与访问层（GVA、数据操作、传输管理） |
| `smem/` | 14,504 | 70 | 语义与接口层（BM API、SHM API、Trans API） |

## 支持的硬件平台

| 硬件型号 | 支持的传输方式 |
|----------|----------------|
| 昇腾 A3 超节点 | Device UB 1.0, Host RDMA |
| 昇腾 A2 服务器 | Device RDMA, Host RDMA |
| 鲲鹏服务器 | Host RDMA |
| 鲲鹏超节点 | Host UB |

## 访问模式支持

| 池化类型 | 访问方向 | Host RDMA | Device RDMA | Device UB 1.0 |
|----------|----------|-----------|-------------|---------------|
| DRAM POOL | LD2GH    | 支持      | 支持         | 支持          |
| DRAM POOL | GH2LD    | 支持      | 支持         | 支持          |
| DRAM POOL | LH2GH    | 支持      | 支持         | 支持          |
| DRAM POOL | GH2LH    | 支持      | 支持         | 支持          |
| HBM POOL  | GD2LH    | 不支持    | 支持         | 支持          |
| HBM POOL  | LH2GD    | 不支持    | 支持         | 支持          |
| HBM POOL  | GD2LD    | 不支持    | 支持         | 支持          |
| HBM POOL  | LD2GD    | 不支持    | 支持         | 支持          |
| HBM+DRAM | GH2GD    | 不支持    | 支持         | 支持          |
| HBM+DRAM | GD2GH    | 不支持    | 支持         | 支持          |
| HBM+DRAM | GH2GH    | 不支持    | 支持         | 支持          |
| HBM+DRAM | GD2GD    | 不支持    | 支持         | 支持          |

**符号说明**:
- L (Local): 本地
- D (Device): 设备
- G (Global): 全局内存池
- H (Host): 主机

## 编译构建

### 构建选项

| 选项 | 说明 | 默认值 |
|------|------|--------|
| `BUILD_UT` | 是否编译单元测试 | OFF |
| `BUILD_OPEN_ABI` | 是否使用 _GLIBCXX_USE_CXX11_ABI | ON |
| `ENABLE_CPU_MONOTONIC` | 启用 CPU 指令获取单调时间 | OFF |
| `BUILD_PYTHON` | 是否编译 Python 模块 | ON |
| `ENABLE_PTRACER` | 是否启用性能打点工具 | OFF |
| `BUILD_TEST` | 是否编译测试工具和示例 | OFF |
| `BUILD_HCOM` | 是否编译 HCOM 模块 | OFF |

### 编译命令

```bash
# 基础编译
mkdir build && cd build
cmake ..
make -j

# 编译单元测试
cmake -DBUILD_UT=ON ..
make -j

# 编译测试示例
cmake -DBUILD_TEST=ON ..
make -j
```
